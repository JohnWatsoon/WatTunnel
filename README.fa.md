## نصب

دو سرور لینوکس با systemd (amd64 یا arm64) و دسترسی root لازم دارید. **اول سرور خارج را راه بیندازید**؛ توکن را سرور خارج می‌سازد.

**۱. نصب روی هر دو سرور**

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<details>
<summary>گیت‌هاب روی سرور ایران بسته است؟ (نصب و آپدیت آفلاین)</summary>

<div dir="rtl">

**روش پیشنهادی — بسته‌ی آفلاین امضاشده (بدون نیاز به دسترسی به گیت‌هاب روی ایران):**

۱. روی **سرور خارج** (بعد از نصب WatTunnel)، یک بسته‌ی آفلاین بسازید و به سرور ایران بفرستید:

</div>

```bash
wattun bundle amd64          # writes wattun-offline-amd64.tar.gz (or arm64)
scp wattun-offline-amd64.tar.gz root@IRAN_IP:/root/
```

<div dir="rtl">

۲. روی **سرور ایران**، بدون نیاز به اینترنت خارجی نصب یا آپدیت کنید (با بررسی امضای دیجیتال RSA):

</div>

```bash
# Fresh install:
tar xzf /root/wattun-offline-amd64.tar.gz -C /root && bash /root/wattun-offline-amd64/install.sh

# Update an existing install later:
wattun update --from /root/wattun-offline-amd64.tar.gz
```

<div dir="rtl">

**روش جایگزین — آینه یا پروکسی SOCKS5/HTTP:**

</div>

```bash
WAT_PROXY=https://ghproxy.net/ bash <(curl -fsSL https://ghproxy.net/https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
# or with a local SOCKS5/HTTP proxy:
WAT_CURL_PROXY=socks5h://127.0.0.1:1080 bash install.sh
```

<div dir="rtl">

در منوی `wattun` ← `s` (تنظیمات) ← `p` هم می‌توانید آدرس آینه یا پروکسی را یک بار ذخیره کنید تا آپدیت‌های بعدی با `wattun update` خودکار از همان مسیر انجام شوند. همچنین می‌توانید فایل‌های `wattun-linux-amd64`، `install.sh`، `wattun-manager`، `SHA256SUMS` و `SHA256SUMS.sig` را از صفحه‌ی [Releases](https://github.com/JohnWatsoon/WatTunnel/releases) در یک پوشه بگذارید و `bash install.sh` را اجرا کنید.

</div>
</details>

<div dir="rtl">

**۲. سرور خارج.** دستور `wattun` را بزنید، بعد `n` (تونل جدید)، گزینه‌ی **Kharej** و نوع اتصال **Auto**. آخر کار یک توکن می‌گیرید:

</div>

```
wat1:aWNtcHwyMDMuMC4xMTMuMTB8a1E3...
```

<div dir="rtl">

**۳. سرور ایران.** `wattun` ← `n` ← **Iran** و توکن را paste کنید. منو همه‌ی روش‌های اتصال را تست می‌کند و سریع‌ترینِ سالم را پیشنهاد می‌دهد؛ Enter را بزنید. بعد پورت‌های سرویستان را وارد کنید، مثلاً `443, 8443:443, 53/udp`. `8443:443` یعنی کاربر به پورت ۸۴۴۳ سرور ایران وصل می‌شود و به پورت ۴۴۳ سرور خارج می‌رسد.

</div>

```
  ✔ Writing key and config
  ✔ Starting wattun@iran
  ✔ CONNECTED (RTT 41.3 ms)

  users ──► Iran :8443 ══ tcp ══► Kharej ──► 127.0.0.1:443
```

<div dir="rtl">

تمام! در کانفیگ کاربرها آی‌پی سرور ایران را بگذارید. سرور خارج فقط به `127.0.0.1` خودش وصل می‌شود.

> **مهم (جلوگیری از فیلتر شدن آی‌پی ایران):** WatTunnel فقط مسیر **ایران ⇄ خارج** را رمزنگاری می‌کند. اینباند پنل شما روی خارج (کانفیگی که دست کاربر می‌دهید) **حتماً باید خودش هم رمزنگاری داشته باشد** — مثل **VLESS+Reality**، **VLESS+WS+TLS**، **VLESS Encryption (PQ)** یا **Shadowsocks 2022**. کانفیگ‌های بدون رمزنگاری مثل `VLESS + TCP header` بین کاربر و سرور ایران به شکل خام رد می‌شوند و فایروال مخابرات/اپراتور خیلی سریع سرور ایران را شناسایی و مسدود می‌کند.

**حالت Auto ترافیک مصرف می‌کند.** منیجر بدترین حالت را پیش از شروع نشان می‌دهد: تا ۱۱۸۴ مگابایت برای تست معمولی و روی مسیر فیلترشده خیلی کمتر (پیش‌تنظیم *+ Extended* در صفحه‌ی تست، ۱۳ کریر شکلی را هم اضافه می‌کند؛ تا ۴۱۶ مگابایت بیشتر). اگر سرورتان حجمی حساب می‌شود، روش را خودتان انتخاب کنید:

| مسیر شما | روش |
|---|---|
| فقط پینگ رد می‌شود | `icmp` |
| UDP باز است | `udp` (کمترین تأخیر) |
| TCP باز است | `tcp`، یا `tls` تا شبیه HTTPS باشد |
| فقط کلودفلر بیرون می‌رود یا دامنه از روی SNI بسته می‌شود | `wss` از پشت کلودفلر ([راهنمای CDN](docs/TECHNICAL.md#cdn-tuning)) |
| فقط سرور خارج می‌تواند به ایران وصل شود | یکی از بالایی‌ها با [حالت معکوس](docs/TECHNICAL.md#reverse-mode) |

## کار روزمره

`wattun` داشبورد را باز می‌کند. شماره‌ی هر تونل صفحه‌اش را باز می‌کند (لاگ، عیب‌یابی، تست سرعت، پورت‌ها و عوض کردن روش اتصال با **c**)، `u` آپدیت می‌کند و `s` تنظیمات برگشت به نسخه‌ی قبل و ترمیم خودکار است. ترمیم خودکار تونل ایرانی را که ۳ دقیقه قطع مانده ری‌استارت می‌کند.

</div>

```bash
wattun status          # one line per tunnel
wattun test NAME       # connection doctor + speed test
wattun ports NAME      # edit port mappings (applied live)
wattun bundle          # build a signed offline archive on Kharej for Iran
wattun update          # update the binary and the menu (or: wattun update --from FILE.tar.gz)
```

<div dir="rtl">

| وضعیت | معنی |
|---|---|
| `up` | لینک کار می‌کند (حتی وقتی تونل خودکار از کریرهای پس‌زمینه وصل است) |
| `partial` | لینک کار می‌کند ولی یکی از کریرهای باند قطع است؛ صفحه‌ی تونل تعدادش را نشان می‌دهد |
| `waiting` / `down` | لینک نیست (روی خارج `waiting`، روی ایران `down`) |
| `unknown` | آمار تونل جواب نداد، پس وضعیت معلوم نیست |
| `stopped` | سرویس اجرا نمی‌شود |

**حالت خودکار همیشه باز و پورت‌های تصادفی.** تونل خودکار خارج همیشه یک تونل واحد نشان داده می‌شود و همه‌ی کریرهای آزمایشی‌اش را به‌شکل خودکار روی پورت‌های آزادِ تصادفی (`۱۰۰۰۰` تا `۳۲۷۶۷`؛ پورت‌های رایجی مثل `۴۴۳`، `۸۰`، `۸۰۸۰` و `۸۴۴۳` را نمی‌گیرد مگر خودتان بخواهید یا `--cdn-domain` بدهید) در پس‌زمینه باز نگه می‌دارد. بنابراین ایران هر زمان می‌تواند بدون نیاز به باز کردن دستی پورت‌ها یا تداخل با پنل‌ها دوباره تست بگیرد (`wattun auto-test NAME`)، باند بسازد یا هنگام قطعی به‌صورت خودکار جابه‌جا شود. تونل‌های محدودشده‌ی نسخه‌های ۳٫۳٫۳ تا ۳٫۳٫۷ هم بعد از آپدیت خودکار دوباره کامل باز می‌شوند.

## جفت‌سازی (Scepter): یک بار جفت کنید، از ایران مدیریت کنید

<div dir="rtl">

**نسخه‌ی ۴٫۰٫۰: تونل‌های قدیمی خودشان به خارج وصل می‌شوند (هر دو سرور را به‌روز کنید).** تونل‌هایی که پیش از ۳٫۵ ساخته شده‌اند در توکنشان جفت‌سازی ندارند. وقتی هر دو سرور ۴٫۰٫۰ باشند، این تونل‌ها طوری جفت می‌شوند که انگار توکنشان `pair=full` داشته: اولین سرور ایرانی که وصل شود آن خارج را برای خودش برمی‌دارد، و پنل وب و دکمه‌ی «Update all» بدون چسباندن هیچ توکنی به آن می‌رسند. اگر اول ایران را به‌روز کنید هم مشکلی نیست: حداکثر ۳۰ ثانیه بعد از به‌روز شدن خارج، بدون ری‌استارت وصل می‌شود. با `pairing: false` در کانفیگ یک تونل، آن تونل از این کار بیرون می‌ماند. هر کسی که توکن یک تونل قدیمی را داشته باشد می‌تواند زودتر از شما آن خارج را بردارد؛ پس ایران را پیش از خارج یا هم‌زمان با آن به‌روز کنید. برای سپردن یک خارج به سرور ایرانی دیگر، روی خارج `wattun pair-token` و روی ایرانِ تازه `wattun add-kharej` را بزنید.

**نسخه‌ی ۳٫۶٫۱: جفت‌سازی در یک قدم (هر دو سرور باید ۳٫۶٫۱ باشند).** نصب‌کننده نقش سرور را می‌پرسد. روی خارج همان لحظه **توکن جفت‌سازی** را نشان می‌دهد؛ بعدها هم با اجرای `wattun` و زدن `t` در داشبورد دوباره دیده می‌شود، با دکمه‌ی چرخاندن (توکن قبلی دیگر کار نمی‌کند و سرور ایران باید این خارج را دوباره اضافه کند). روی ایران، `t` در داشبورد (یا `a` در صفحه‌ی Kharej servers، یا دکمه‌ی **Add Kharej** در پنل وب) همان توکن را می‌گیرد، می‌سنجد کدام کریرها به خارج می‌رسند و جفت می‌کند. یک سرور ایران می‌تواند این‌طور چند خارج اضافه کند. پشت این کار یک **لینک جفت‌سازی** کوچک است: تونلی جدا که فقط کانال مدیریت را حمل می‌کند. این تونل هیچ‌وقت در فهرست تونل‌ها دیده نمی‌شود و فقط در صفحه‌ی سرورهای خارج با عنوان «pairing link» می‌آید؛ heal و راه‌اندازی همه‌ی تونل‌ها آن را روشن نگه می‌دارند. بعد از آن تونل‌ها از ایران ساخته می‌شوند: New tunnel، گزینه‌ی «On Kharej and here». فرمان‌ها `wattun pair-token [--rotate]` روی خارج، و `wattun add-kharej --token wat1:...` و `wattun remove-kharej HOST` روی ایران هستند. حذف یک خارج تونل‌هایش را خاموش نمی‌کند. جفت‌هایی که قبلاً با توکن تونل ساخته شده‌اند مثل قبل کار می‌کنند.

</div>

نسخه‌ی ۳٫۵٫۰ یک جفت‌سازی اختیاری میان دو سرور اضافه می‌کند (هر دو سر باید ۳٫۵٫۰ باشند) و آن را کاملاً خودکار می‌کند — نصب هیچ گام دستی جفت‌سازی ندارد: روی خارج وات‌تانل را نصب کنید و در منیجر تونل اول را بسازید (توکنی که فقط یک بار چاپ می‌شود جفت‌سازی را درون خودش حمل می‌کند و منیجر پورت قفل را هم خودش در کانفیگ سرور می‌نویسد)، روی ایران نصب کنید و همان توکن را بچسبانید — کابین آماده است. توکن فقط جفت‌سازی را شروع می‌کند: اولین سرور ایرانی که وصل شود کلید تازه‌ی خودش را می‌گیرد و از آن به بعد توکن به‌تنهایی نمی‌تواند خارج را مدیریت کند (تونل را همچنان راه می‌اندازد). بعد از نصب دیگر هیچ SSH‌ای به خارج لازم نیست. از آن به بعد تونل یک کانال مدیریتی رمزنگاری‌شده و پنهان با خودش حمل می‌کند — یک جریان رزروشده درون رمزنگاری نشست که روی اعتبارش رتبه‌ی توانمندی نوشته شده (`tunnel` < `create` < `manage` < `full`) و هر فرمان روی خارج بررسی، محدودسازی نرخ و ثبت در دفتر رویداد می‌شود. اگر تونل قطع شود، زنده‌کردنش خودکار است: خودش به تلاش برای اتصال ادامه می‌دهد، و اگر کانفیگ ایران هم پورت قفل را داشته باشد با **قفل scepter** خارج تماس می‌گیرد — بار اول بعد از ۳۰ ثانیه و بعد با فاصله‌ی بیشتر، تا هر ۱۰ دقیقه یک بار — شنونده‌ی wss شکل‌داری که وقتی همه‌ی تونل‌های جفت قطع باشند باز می‌شود — تا کانال مدیریتی دوباره برقرار شود؛ تماس‌گیرنده باید پیش از هر چیز دانستن کلید ۳۲ بایتی جفت‌سازی را ثابت کند و شنونده بعد از اولین تماس بسته می‌شود. تونل معکوس قفل لازم ندارد: آنجا خارج خودش مدام به ایران زنگ می‌زند. این کانال هرگز در هیچ داشبوردی دیده نمی‌شود؛ فقط doctor آن را نشان می‌دهد. چرخاندن کلید جفت‌سازی هم از کابین (ایران) و هم از کنسول خارج ممکن است؛ اما لغو همچنان فقط کار کنسول خودِ خارج است (منوی Pairing، گزینه‌ی revoke) — کانال نباید بتواند خودش را لغو کند؛ همین مرز اعتماد است. خارجِ لغوشده جفت‌نشده می‌ماند تا صاحبش همان‌جا «Allow a new Iran to pair» را بزند؛ اگر سرور ایران را از دست دادید هم راه برگشت همین است. خارج هیچ‌وقت به پورت SSH، متریک یا قفل خودش فوروارد نمی‌کند، هر چه جفت بخواهد.

آنچه ایران از راه این کانال می‌کند — همه از کابین `wattun scepter` در منوی گو (`wattun -scepter-call CMD` شکل تک‌فرمانی و اسکریپت‌پذیر آن است):

| حوزه | فرمان‌ها |
|---|---|
| خواندن | وضعیت زنده، فهرست تونل‌ها، آمار هر تونل، لاگ‌ها، رویدادها، تاریخچه |
| نوشتن | ساخت، ویرایش و حذف تونل، start/stop/restart، سقف هر پورت، پیش‌تنظیم‌ها — هر فرمان «بررسی ← پشتیبان ← اعمال ← تأیید» است و در خطا برمی‌گردد. تونلی که از ایران ساخته شود هم‌زمان روی هر دو سرور برپا می‌شود، بی‌آنکه توکنی جابه‌جا کنید |
| کار با کریر از راه دور | باز کردن شنونده‌ی آزمایشی روی خارج و تست سرعتش از ایران (`test.open`/`test.close`)، عوض کردن کریر یک تونل دوردست با برگشت خودکار (`carrier.change`)، اجرا و اعمال رتبه‌بندی کریرها (`auto.test`/`auto.rows`/`auto.apply`) |
| بهره‌برداری | آپدیت باینری خارج با نگهبان برگشت به نسخه‌ی قبل (`update.run`)، خروجی ساخت‌یافته‌ی doctor، پشتیبان کامل کانفیگ به شکل tarball تأییدشده، دفتر رویداد |

جزئیات و جدول کامل فرمان‌ها: [TECHNICAL.md](docs/TECHNICAL.md#scepter-the-pairing-and-management-plane-350).

## پنل وب (سرور ایران)

<div dir="rtl">

نسخه‌ی ۳٫۶٫۰ یک داشبورد مرورگری اختیاری روی سرور ایران می‌آورد: دانلود و آپلود زنده‌ی هر تونل، نشانگر سلامت، نگهبان قطعی ۲۴ ساعته، تاریخچه و لاگ هر تونل، و سرورهای خارجِ جفت‌شده که از راه کانال scepter دیده می‌شوند. مدیریت هم از همین پنل انجام می‌شود: روشن و خاموش کردن و راه‌اندازی دوباره‌ی تونل‌ها، پورت‌ها و محدودیت‌ها، تست سرعت، ساختن تونل تازه (روی خارج و ایران با هم، در یک مرحله)، حذف، آپدیت و برگشت به نسخه‌ی قبل، پشتیبان‌گیری و بازگردانی، آمار ترافیک ۳۰ روز، هشدارها، و گواهی خود پنل (گواهی خودتان، یک CA خصوصی برای گوشی، یا ACME برای دامنه یا آی‌پی خود سرور). مصرف و سهمیه‌ی هر پورت را هم نشان می‌دهد و صفرش می‌کند، اعتبار جفت‌شدن با خارج را عوض یا فراموش می‌کند، تونل را روی هر دو سرور با هم حذف می‌کند، خودش را به پورت دیگری می‌برد، فایل پشتیبان را با یک عبارت عبور رمزگذاری می‌کند، پیش از بازگردانی نشان می‌دهد چه چیزی عوض می‌شود، برای پر شدن سهمیه، نسخه‌ی تازه و افت سرعت هشدار می‌دهد، و تاریخ‌ها را می‌تواند به تقویم شمسی نشان دهد. تست کریرها زنده در خود صفحه دیده می‌شود و وقتی تمام شد، می‌توانید هر کریری را که کار کرد انتخاب کنید یا چندتایش را با هم باند کنید؛ حالت باند و مسیرهای یک تونل باندشده (بی‌صدا کردن و برگرداندن هر مسیر) هم در کشوی همان تونل است. نقشه جای واقعی سرورها را پیدا می‌کند؛ برای این کار از یک سرویس مکان‌یابی آی‌پی می‌پرسد، پس آن سرویس آی‌پی سرورهایتان را می‌بیند. کارهایی که کلید را نشان می‌دهند یا برگشت ندارند، ورود دومرحله‌ای را لازم دارند و هر بار رمز و یک کد تازه می‌خواهند.

وقتی در نصب‌کننده «ایران» را انتخاب کنید، می‌پرسد پنل وب روشن شود یا نه (Enter یعنی بله). اگر بعداً خواستید، یا سرورتان از قبل نصب است:

</div>

```bash
wattun panel on        # prints the address, user and password (shown once) and a QR code
wattun panel 2fa       # optional: authenticator app 2FA from the console (or in the panel's Settings)
wattun panel off       # stop it; --forget also deletes its address and password
```

<div dir="rtl">

پنل روی یک پورت تصادفی و پشت یک مسیر مخفی تصادفی بالا می‌آید و گواهی خودش را می‌سازد؛ سرورهای ایران معمولاً نمی‌توانند از مراکز صدور گواهی بگیرند، پس مرورگر بار اول هشدار می‌دهد: اثر انگشتی را که کنسول چاپ کرد با آنچه مرورگر نشان می‌دهد مقایسه کنید و بعد بپذیرید. هر آدرسی بیرون از مسیر مخفی مثل صفحه‌ی ۴۰۴ پیش‌فرض nginx به نظر می‌رسد، و ۵ بار رمز اشتباه آن آی‌پی را ۱۵ دقیقه مسدود می‌کند. ورود دومرحله‌ای با اپ احراز هویت و ۱۰ کد بازیابی یک‌بارمصرف هم در تنظیمات پنل هست.

جزئیات: [TECHNICAL.md](docs/TECHNICAL.md#web-panel-360).

## این ابزار چه می‌کند

WatTunnel سرور **ایران** (جایی که کاربرها وصل می‌شوند) را به سرور **خارج** (جایی که سرویس شما اجرا می‌شود) وصل می‌کند و هر پورت TCP و UDP را بینشان می‌رساند. یک فایل اجرایی است، بدون هیچ وابستگی.

- **از هر راهی که مسیرتان باز گذاشته رد می‌شود:** `icmp`، `udp`، `tcp`، `tls`، `ws`، `wss`، `h2`، `h2c`، `grpc`، `gre`، `ipip`، کلودفلر با ECH، حالت معکوس، یا چند روش با هم در یک تونل.
- **کنترل دستی باند:** یک کریر باند را می‌شود با پسوند جهت به یک سمت محدود کرد (`carrier: tcp:up+udp:down`؛ هر دو سرور باید نسخه‌ی یکسان داشته باشند)، `-mtu-adapt` وقتی اپراتور بسته‌های بزرگ را حذف می‌کند ولی بسته‌های کوچک رد می‌شوند اندازه‌ی بار همان مسیر را خودبه‌خود کم می‌کند (پیش‌فرض خاموش، جدا برای هر سر، برای طرف مقابل نامرئی)، و `wattun mute NAME PATH` و `wattun unmute NAME PATH` یک کریر را بدون ری‌استارت از مدار خارج می‌کنند یا برمی‌گردانند.
- **از فیلتر می‌گذرد:** SNI جعلی، `udp-dns`، `udp-hop` (هر چند بسته از یک پورت مبدأ تازه می‌فرستد، برای مسیری که هر جریان UDP را بعد از حدود ۳۰ بسته قطع می‌کند)، `tcp-mimic`، چرخش اتصال‌ها با `pool-rotate`، و `wattun matrix NAME` که ترکیب‌ها را امتحان می‌کند و بهترین را می‌گذارد. `wattun blackout NAME` کل جعبه‌ابزار را روشن می‌کند.
- **سخت شناسایی می‌شود:** هیچ بایت ثابتی در سرآیند بسته نیست، بسته‌های بیکار اندازه‌ی تصادفی دارند، کریرهای HTTP مثل nginx جواب می‌دهند (یا با `decoy` درخواست‌های غریبه را به یک سایت واقعی می‌سپارند)، و ۱۳ کریر شکلی مثل `vxlan` و `ntp-direct` هم هست. `shape-data` و `noise` اختیاری‌اند و پهنای باند خرج می‌کنند.
- **خودش را تنظیم می‌کند:** پیش‌فرض‌ها از هسته و رم سرور می‌آیند و تست خودکار، نشست و اتصال را روی مسیر شما تنظیم می‌کند.
- **افت بسته کندش نمی‌کند:** سرعت از روی تأخیر تنظیم می‌شود و `fec: auto` پریتی را فقط وقتی می‌فرستد که واقعاً بسته از دست می‌رود.
- **خودش را نگه می‌دارد:** تغییر پورت بدون ری‌استارت، آمار و سقف حجم برای هر پورت (که می‌شود هر روز، هفته یا ماه از صفر شروع شود)، ترمیم خودکار، آپدیت با برگشت به نسخه‌ی قبل.

### روی مسیرهای فیلترشده

روی مسیری که **هر جریان مستقیم ایران ← خارج را در کمتر از یک ثانیه می‌برد** (UDP بعد از ۳ بسته، TCP بعد از ۳ کیلوبایت، روی همه‌ی پورت‌ها و با هر محتوا)، تونل معمولی یک لحظه وصل می‌شود و می‌میرد. نتیجه از میان همان فیلتر (۳٫۰٫۰، یک هسته روی هر سرور، ۸۲ میلی‌ثانیه، از هر روش یک اجرا؛ پس در حد مرتبه‌ی بزرگی بخوانید):

| روش | دانلود | آپلود |
|---|---|---|
| `udp-dns` مستقیم: هر بسته شبیه DNS روی پورت ۵۳ | **۳۶ مگابایت** | **۲۹ مگابایت** |
| `tcp` مستقیم + `fake-sni` با حالت `rst`، با `pool-rotate` | ۲۸ مگابایت | ۳۲ مگابایت |
| `tcp` معکوس (خارج به ایران وصل می‌شود)، با `pool-rotate` | ۲۸ مگابایت | ۳۲ مگابایت |
| `wss` / `tls` / `h2` معکوس | ۲۲ تا ۲۵ مگابایت | ۲۷ تا ۳۰ مگابایت |
| `udp` معکوس (ایران هیچ‌وقت اول بسته نمی‌فرستد) | ۲۱ مگابایت | ۱۹ مگابایت |

روی مسیر دیگری که کلودفلر فقط جریان‌هایی با نام `www.cloudflare.com` را رد می‌کند، `wss` با `fake-mode: rst` در ۲ ثانیه وصل شد: ۹ تا ۱۵ مگابایت دانلود و ۲ تا ۵ مگابایت آپلود ([آزمایش میدانی](docs/TECHNICAL.md#fake-sni-field-test-21012)).

## مصرف منابع

تونل بیکار حدود ۲ بسته‌ی کوچک در ثانیه می‌فرستد: روی `udp` یا `icmp` روزی حدود ۱۱٫۵ مگابایت، با ۰٫۱ تا ۰٫۲ درصد یک هسته و ۱۰ تا ۱۷ مگابایت رم. تونل ICMP شلوغ با ۲۵۰ تا ۳۰۰ کاربر با حدود ۴۰ مگابایت کار می‌کند. زیر بار، سربار روی `tcp` ۰٫۲۵ درصد و روی `udp` یا `icmp` با `mtu: 1400` حدود ۵ درصد است. [جزئیات](docs/TECHNICAL.md#resource-usage-idle-ram-cpu-and-bandwidth).

## امنیت

- **رمزنگاری:** ChaCha20-Poly1305 با تبادل X25519 در هر نشست؛ پس اگر فایل کلید بعدها لو برود، ترافیک ضبط‌شده خوانده نمی‌شود.
- **فقط بخش ایران ⇄ خارج محافظت می‌شود.** بین کاربرها و ایران، یک پروتکل رمزنگاری‌شده‌ی سرتاسری مثل VLESS+Reality، TLS یا وایرگارد داخل تونل اجرا کنید.
- **توکن کلید را در خود دارد.** مثل رمز عبور با آن رفتار کنید و فقط در کانال خصوصی بفرستید.
- **سرور خارج فقط به `127.0.0.1` خودش وصل می‌شود،** آن هم فقط پورت‌های مجاز. روی کریرهای مستقیم، `allow-clients` کلید را به IPهایی که نام می‌برید هم محدود می‌کند. `metrics` را روی `127.0.0.1` نگه دارید.
- **نصب امضاشده:** نصاب فایل اجرایی و منیجر را با `SHA256SUMS` امضاشده (RSA) می‌سنجد و امضای نادرست را رد می‌کند. خود اسکریپتی که از آینه گرفته می‌شود فقط در اولین استفاده قابل اعتماد فرض می‌شود.
- **آنچه در شبکه دیده می‌ماند:** آدرس سرور و حجم و زمان‌بندی بسته‌ها.

اینکه هر گزینه‌ی ضدسانسور چه چیزی را پنهان می‌کند و چه چیزی را نه: [جعل و شکل‌دهی](docs/TECHNICAL.md#spoofing-and-shaping-explained). جزئیات کامل: [مدل امنیتی](docs/TECHNICAL.md#security-model).
