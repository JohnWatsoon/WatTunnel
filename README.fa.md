## نصب

دو سرور لینوکس با systemd (amd64 یا arm64) و دسترسی root لازم دارید. **اول سرور خارج را راه بیندازید**؛ توکن را سرور خارج می‌سازد.

**۱. نصب روی هر دو سرور**

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<details>
<summary>گیت‌هاب روی سرورتان باز نمی‌شود؟</summary>

```bash
WAT_PROXY=https://ghproxy.net/ bash <(curl -fsSL https://ghproxy.net/https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<div dir="rtl">

این پروکسی یک آینه‌ی ثالث است. فایل اجرایی و منیجر همچنان با ریلیز امضاشده سنجیده می‌شوند، ولی `install.sh` که از آینه می‌گیرید نه؛ پس اگر می‌توانید، فایل‌های ریلیز یا `git clone` را ترجیح دهید.

راه دیگر: فایل‌های `wattun-linux-amd64`، `install.sh` و `wattun-manager` را از صفحه‌ی [Releases](https://github.com/JohnWatsoon/WatTunnel/releases) بگیرید، فایل اجرایی را داخل پوشه‌ی `dist/` کنار `install.sh` بگذارید و `bash install.sh` را بزنید.

</div>
</details>

<div dir="rtl">

**۲. سرور خارج.** دستور `wattun` را بزنید، بعد `n` (تونل جدید)، گزینه‌ی **Kharej** و نوع اتصال **Auto**. آخر کار یک توکن می‌گیرید:

</div>

```
wat1:aWNtcHwyMDMuMC4xMTMuMTB8a1E3...
```

<div dir="rtl">

**۳. سرور ایران.** `wattun` ← `n` ← **Iran** و توکن را paste کنید. منو همه‌ی روش‌های اتصال را تست می‌کند و سریع‌ترینِ سالم را پیشنهاد می‌دهد؛ Enter را بزنید. بعد پورت‌های سرویستان را وارد کنید، مثلاً `443, 8443:443, 53/udp`. `8443:443` یعنی کاربر به پورت ۸۴۴۳ سرور ایران وصل می‌شود و به پورت ۴۴۳ سرور خارج می‌رسد.

</div>

```
  ✔ Writing key and config
  ✔ Starting wattun@iran
  ✔ CONNECTED (RTT 41.3 ms)

  users ──► Iran :8443 ══ tcp ══► Kharej ──► 127.0.0.1:443
```

<div dir="rtl">

تمام! در کانفیگ کاربرها آی‌پی سرور ایران را بگذارید. سرور خارج فقط به `127.0.0.1` خودش وصل می‌شود.

**حالت Auto ترافیک مصرف می‌کند.** منیجر بدترین حالت را پیش از شروع نشان می‌دهد: تا ۱۱۸۴ مگابایت برای تست معمولی، حدود ۴۱۶ مگابایت بیشتر اگر توکن با `--extended` ساخته شده باشد، و روی مسیر فیلترشده خیلی کمتر. اگر سرورتان حجمی حساب می‌شود، روش را خودتان انتخاب کنید:

| مسیر شما | روش |
|---|---|
| فقط پینگ رد می‌شود | `icmp` |
| UDP باز است | `udp` (کمترین تأخیر) |
| TCP باز است | `tcp`، یا `tls` تا شبیه HTTPS باشد |
| فقط کلودفلر بیرون می‌رود یا دامنه از روی SNI بسته می‌شود | `wss` از پشت کلودفلر ([راهنمای CDN](docs/TECHNICAL.md#cdn-tuning)) |
| فقط سرور خارج می‌تواند به ایران وصل شود | یکی از بالایی‌ها با [حالت معکوس](docs/TECHNICAL.md#reverse-mode) |

## کار روزمره

`wattun` داشبورد را باز می‌کند. شماره‌ی هر تونل صفحه‌اش را باز می‌کند (لاگ، عیب‌یابی، تست سرعت، پورت‌ها و عوض کردن روش اتصال با **c**)، `u` آپدیت می‌کند و `s` تنظیمات برگشت به نسخه‌ی قبل و ترمیم خودکار است. ترمیم خودکار تونل ایرانی را که ۳ دقیقه قطع مانده ری‌استارت می‌کند.

</div>

```bash
wattun status          # one line per tunnel
wattun test NAME       # connection doctor + speed test
wattun ports NAME      # edit port mappings (applied live)
wattun update          # update the binary and the menu
```

<div dir="rtl">

| وضعیت | معنی |
|---|---|
| `up` | لینک کار می‌کند، حتی اگر لینک تونل خودکار روی سمت دیگرش باشد |
| `partial` | لینک کار می‌کند ولی یکی از کریرهای باند قطع است؛ صفحه‌ی تونل تعدادش را نشان می‌دهد |
| `standby` | سمتی از تونل خودکار که ایران از آن استفاده نمی‌کند |
| `waiting` / `down` | لینک نیست (روی خارج `waiting`، روی ایران `down`) |
| `unknown` | آمار تونل جواب نداد، پس وضعیت معلوم نیست |
| `stopped` | سرویس اجرا نمی‌شود |

**بعد از انتخاب ایران،** تونل خودکار خارج حدود ۵ دقیقه بعد هر چیز بی‌استفاده را می‌بندد و سمتی را که باز می‌ماند ری‌استارت می‌کند، پس اتصال‌هایش یک بار قطع می‌شوند. برای عوض کردن روش یا تست دوباره، اول روی خارج همه را باز کنید:

</div>

```bash
wattun-manager auto-widen NAME
```

<div dir="rtl">

اگر این کار را نکنید، منیجر بعد از ۳ بررسی ناموفق خودش همه را باز می‌کند (حداکثر یک بار در هر ۱۰ دقیقه). برای باز نگه داشتن همه‌ی روش‌ها: `wattun-manager auto-prune NAME --keep-open`.

## این ابزار چه می‌کند

WatTunnel سرور **ایران** (جایی که کاربرها وصل می‌شوند) را به سرور **خارج** (جایی که سرویس شما اجرا می‌شود) وصل می‌کند و هر پورت TCP و UDP را بینشان می‌رساند. یک فایل اجرایی است، بدون هیچ وابستگی.

- **از هر راهی که مسیرتان باز گذاشته رد می‌شود:** `icmp`، `udp`، `tcp`، `tls`، `ws`، `wss`، `h2`، `h2c`، `grpc`، `gre`، `ipip`، کلودفلر با ECH، حالت معکوس، یا چند روش با هم در یک تونل.
- **از فیلتر می‌گذرد:** SNI جعلی، `udp-dns`، `tcp-mimic`، چرخش اتصال‌ها با `pool-rotate`، و `wattun matrix NAME` که ترکیب‌ها را امتحان می‌کند و بهترین را می‌گذارد. `wattun blackout NAME` کل جعبه‌ابزار را روشن می‌کند.
- **سخت شناسایی می‌شود:** هیچ بایت ثابتی در سرآیند بسته نیست، بسته‌های بیکار اندازه‌ی تصادفی دارند، کریرهای HTTP مثل nginx جواب می‌دهند، و ۱۳ کریر شکلی مثل `vxlan` و `ntp-direct` هم هست. `shape-data` و `noise` اختیاری‌اند و پهنای باند خرج می‌کنند.
- **خودش را تنظیم می‌کند:** پیش‌فرض‌ها از هسته و رم سرور می‌آیند و تست خودکار، نشست و اتصال را روی مسیر شما تنظیم می‌کند.
- **افت بسته کندش نمی‌کند:** سرعت از روی تأخیر تنظیم می‌شود و `fec: auto` پریتی را فقط وقتی می‌فرستد که واقعاً بسته از دست می‌رود.
- **خودش را نگه می‌دارد:** تغییر پورت بدون ری‌استارت، آمار و سقف حجم برای هر پورت، ترمیم خودکار، آپدیت با برگشت به نسخه‌ی قبل.

## سرعت

سرورهای واقعی، مسیر بدون فیلتر. جدول‌های کامل و روش اندازه‌گیری: [docs/TECHNICAL.md](docs/TECHNICAL.md#field-numbers).

| نوع اتصال | دانلود | آپلود | پینگ زیر بار |
|---|---|---|---|
| **`tcp` با تنظیمات پیش‌فرض** (۳٫۲٫۰، جفت سرور ۲ هسته‌ای، ۸۰ میلی‌ثانیه، ۱۶ جریان) | **۲۲۴ تا ۲۸۲ مگابایت (۲۷۲ مگابایت پیوسته = ۲٫۱۷ گیگابیت)** | ۱۴۶ مگابایت | - |
| **`tls`** (همان جفت سرور) | ۱۸۷ تا ۲۰۹ مگابایت | ۱۴۰ مگابایت | - |
| **TCP / TLS / معکوس** (۲٫۵٫۱، تونل واقعی با کاربر) | ۱۹۵ مگابایت | ۲۷۶ مگابایت | ۴۰ تا ۵۱ میلی‌ثانیه |
| **ICMP** (مسیری که فقط پینگ از آن رد می‌شود) | تا حدود ۳۳ مگابایت، یعنی سقف خود مسیر | ۲۶ مگابایت | ۴۰ تا ۴۵ میلی‌ثانیه |
| **کلودفلر** (`wss` با ECH، ۴ نشست) | ۴۴ تا ۴۸ مگابایت | تا ۸۲ مگابایت | ۱۰۹ تا ۱۱۶ میلی‌ثانیه (پایه‌ی کلودفلر ۸۶) |

### روی مسیرهای فیلترشده

روی مسیری که **هر جریان مستقیم ایران ← خارج را در کمتر از یک ثانیه می‌برد** (UDP بعد از ۳ بسته، TCP بعد از ۳ کیلوبایت، روی همه‌ی پورت‌ها و با هر محتوا)، تونل معمولی یک لحظه وصل می‌شود و می‌میرد. نتیجه از میان همان فیلتر (۳٫۰٫۰، یک هسته روی هر سرور، ۸۲ میلی‌ثانیه، از هر روش یک اجرا؛ پس در حد مرتبه‌ی بزرگی بخوانید):

| روش | دانلود | آپلود |
|---|---|---|
| `udp-dns` مستقیم: هر بسته شبیه DNS روی پورت ۵۳ | **۳۶ مگابایت** | **۲۹ مگابایت** |
| `tcp` مستقیم + `fake-sni` با حالت `rst`، با `pool-rotate` | ۲۸ مگابایت | ۳۲ مگابایت |
| `tcp` معکوس (خارج به ایران وصل می‌شود)، با `pool-rotate` | ۲۸ مگابایت | ۳۲ مگابایت |
| `wss` / `tls` / `h2` معکوس | ۲۲ تا ۲۵ مگابایت | ۲۷ تا ۳۰ مگابایت |
| `udp` معکوس (ایران هیچ‌وقت اول بسته نمی‌فرستد) | ۲۱ مگابایت | ۱۹ مگابایت |

روی مسیر دیگری که کلودفلر فقط جریان‌هایی با نام `www.cloudflare.com` را رد می‌کند، `wss` با `fake-mode: rst` در ۲ ثانیه وصل شد: ۹ تا ۱۵ مگابایت دانلود و ۲ تا ۵ مگابایت آپلود ([آزمایش میدانی](docs/TECHNICAL.md#fake-sni-field-test-21012)).

## مصرف منابع

تونل بیکار حدود ۲ بسته‌ی کوچک در ثانیه می‌فرستد: روی `udp` یا `icmp` روزی حدود ۱۱٫۵ مگابایت، با ۰٫۱ تا ۰٫۲ درصد یک هسته و ۱۰ تا ۱۷ مگابایت رم. تونل ICMP شلوغ با ۲۵۰ تا ۳۰۰ کاربر با حدود ۴۰ مگابایت کار می‌کند. زیر بار، سربار روی `tcp` ۰٫۲۵ درصد و روی `udp` یا `icmp` با `mtu: 1400` حدود ۵ درصد است. [جزئیات](docs/TECHNICAL.md#resource-usage-idle-ram-cpu-and-bandwidth).

## امنیت

- **رمزنگاری:** ChaCha20-Poly1305 با تبادل X25519 در هر نشست؛ پس اگر فایل کلید بعدها لو برود، ترافیک ضبط‌شده خوانده نمی‌شود.
- **فقط بخش ایران ⇄ خارج محافظت می‌شود.** بین کاربرها و ایران، یک پروتکل رمزنگاری‌شده‌ی سرتاسری مثل VLESS+Reality، TLS یا وایرگارد داخل تونل اجرا کنید.
- **توکن کلید را در خود دارد.** مثل رمز عبور با آن رفتار کنید و فقط در کانال خصوصی بفرستید.
- **سرور خارج فقط به `127.0.0.1` خودش وصل می‌شود،** آن هم فقط پورت‌های مجاز. روی کریرهای مستقیم، `allow-clients` کلید را به IPهایی که نام می‌برید هم محدود می‌کند. `metrics` را روی `127.0.0.1` نگه دارید.
- **نصب امضاشده:** نصاب فایل اجرایی و منیجر را با `SHA256SUMS` امضاشده (RSA) می‌سنجد و امضای نادرست را رد می‌کند. خود اسکریپتی که از آینه گرفته می‌شود فقط در اولین استفاده قابل اعتماد فرض می‌شود.
- **آنچه در شبکه دیده می‌ماند:** آدرس سرور و حجم و زمان‌بندی بسته‌ها.

اینکه هر گزینه‌ی ضدسانسور چه چیزی را پنهان می‌کند و چه چیزی را نه: [جعل و شکل‌دهی](docs/TECHNICAL.md#spoofing-and-shaping-explained). جزئیات کامل: [مدل امنیتی](docs/TECHNICAL.md#security-model).
