# v3.3.0

**Faster, honest auto mode, cleanup that cannot break a bond, a server-side client allowlist, and thirteen new wire
shapes.** Auto mode now measures long enough to rank a fast route, prints the true worst-case traffic including
tuning, and tunes only the settings that actually moved speed. The automatic cleanup on Kharej now touches the unused
**reverse** side only, so a heal pass can no longer narrow a bonded Iran client to one leg. A new admission allowlist
pins a leaked token to source IPs, FEC costs nothing on a healthy link, and thirteen carriers dress each datagram as a
common tunnelling or voice protocol. **Both ends need 3.3.0 for the new carriers**; everything else stays
wire-compatible with older peers, and no config change is required.

## Changes in detail

- **`/speedtest` and auto mode measure 16 streams by default** (was 8; 1-32 is still accepted and `streams=` overrides),
  so the figure reflects what the tunnel does under real multi-connection load instead of one connection's share.
- **Auto measurement is duration-based.** Screening runs an 8 MB probe each way per variant and grows it to 16 MB when
  the measured rate would finish it in under 1.5 s; the top 3 finalists are re-measured with 16 streams for at least
  1.5 s each way (20-40 MB each way), so slow start no longer decides the winner on a fast link.
- **The auto-test budget is printed for all three phases.** `Budget: up to 1184 MB, about 3 min` for a normal plan:
  544 MB screening (17 variants × 2 × 16 MB) + 240 MB finalists (3 × 2 × 40 MB) + 400 MB tuning (10 probes, baseline
  included, × 2 × 20 MB). With a CDN domain the plan has two more variants and the cap is 1248 MB. The minutes assume
  a conservative 8 MB/s, so a fast link finishes sooner and a slow route later; the MB figure is the exact cap. A
  variant that does not connect sends almost nothing, so a filtered route moves far less.
- **Auto tuning is reduced to `sessions` and `conns`** at a fixed 20 MB each way per probe, keeping a value only when
  it beats the best so far by more than 10 %. `mtu`, `win-max`, `batch` and `loss-ceiling` are no longer probed: on
  the test pair their effect sat inside the run-to-run noise. Bonds and reverse variants are still tuned for the knobs
  the engine accepts there (`sessions` is refused on both, so bonds/reverse tune `conns` only).
- **Auto-heal and the off-peak optimizer screen with the same 8-16 MB probes** (up to 544 MB for a full normal plan if
  every variant connects); auto-heal runs one at most every 30 minutes and only after the tunnel failed.
- **Auto now tests `gre` and `ipip` too.** They are raw-IP carriers with no listen port, so the plan carries them as
  bare names (`d=...,gre,ipip`) and Iran screens them like any other direct variant. This needs engine 3.2.0+ on both
  ends; an older side skips them with one hint instead of counting them.
- **Extended Auto (opt-in, both ends 3.3.0).** On Kharej, `--extended` (or the wizard question) also tests the 13
  shaped carriers. Because the engine refuses a shaped leg inside the auto bond, Kharej creates one hidden
  single-carrier unit per shape (`NAME-e-<shape>`, shared key, own metrics port, the parent's `ports:` allowlist,
  `limits:` and `allow-clients`; UDP
  tier gets its conventional or a free fallback port, raw tier no listen). Iran screens them as normal variants (bare
  peer for the raw tier, `addr:port` for the UDP tier) and can pick one. Raw tier needs Linux + root/CAP_NET_RAW and
  cloud firewall protocols 41/50/97/115. Heal/delete/uninstall manage the hidden listeners (their state files and UDP
  firewall rules go with delete/uninstall, and a key change restarts the enabled ones). The default prune reads each
  child's own `/stats`: it keeps the shapes with a live client and stops the rest once one reports a pick, keeps every
  shape when no child reports traffic or a running child's stats cannot be read, and in a shaped-only tunnel with no
  reverse companion narrows on that pick alone after the same grace; `auto-widen` / `auto-prune NAME --direct`
  re-enable them for a retest. An older Iran ignores them and their ports stay open until that cleanup — it is opt-in
  for that reason. Screening adds up to 13 variants (about 416 MB worst case at 16 MB each way); the printed budget
  includes them.
- **Manager: faster to pick a type and to tune it safely.** The connection-type picker gains **More transports
  (advanced)…** for the 13 shaped carriers (single only, same warnings). Auto gre/ipip is visible in the plan; the
  Advanced page is grouped into Performance / Shaping & DPI / Safety / State & data; FEC keeps its one-key `off`/`auto`
  with `a` to open the loss band; `win-max` (4-64) and `loss-ceiling` are editable; keys with no UI path (debug,
  ping-every, udp-idle, tcp-cc, slack-ms, hedge, lanes, mem-budget, plain, header, keep-slow, tls-small-ch, hdr-mask,
  tcp-mimic, tls-pin, fake-ip, fake-split) are listed as file-only expert
  keys. A coverage test keeps every engine flag tied to a UI path or that list; the manager self-test is now 875
  checks (`MGR_VERSION=2026110501`).
- **The auto Kharej cleanup is reverse-side only by default.** After Iran's pick has been stable for `autoprune`
  minutes (`.manager.conf`, default 12, 0 = off), the heal pass stops the stale `wattun-autowatch` helper and closes
  the unused `NAME-r` reverse companion or narrows it to the reverse carriers that are alive. The direct `carrier:`
  list is not rewritten, because the engine reports one carrier per session and cannot tell a bonded Iran client from
  a single leg. Full direct narrowing stays available but is opt-in: `.manager.conf autoprune-direct=1`, or
  `wattun-manager auto-prune NAME --direct`. `auto-prune NAME --keep-open` still opts a tunnel out of both automatic
  passes.
- **The widen safety net is quicker:** a pruned tunnel with no working open carrier for 3 consecutive checks is
  reopened from the full token plan at most once per `autowiden` minutes, now default **10** (was 30; 0 = off), so the
  default cleanup cannot hide a failover path for long.
- **`fec: auto` sends parity only while the link is really losing packets:** above `-fec-on-loss` (2 %), stopping
  below `-fec-off-loss` (0.5 %), with a 2 s dwell. A healthy tunnel sends no parity and the receiver copies no
  plaintexts for reconstruction, so a healthy link pays nothing; new `/stats` field `fec_state` shows the gate. One
  group right after parity resumes cannot be rebuilt (receiver-side heuristic).
- **Idle noise and `shape-data` are opt-in and off by default.** `-shape-data PCT` (0-25 %) pads packets that carry
  stream data to randomized realistic sizes, bounded by a percent of the stream bytes actually sent (plus a 4 KB
  bank). `-noise off|low|med|custom` + `-noise-bps` + `-noise-window HH:MM-HH:MM` sends idle filler at a byte budget
  (`low` ≈ 128 B/s ≈ 11 MB/day, `med` ≈ 1 KB/s ≈ 88 MB/day). The noise budget is **per session**: `-sessions 2`
  doubles it and each Kharej client's session sends its own. Noise now delivers close to the configured rate (the
  old pump capped anything above about 8 KB/s at a fraction of the setting) and no longer keeps the 10-second stats
  line printing on an otherwise idle tunnel. Both count in the session totals and on the host bill, not in the
  per-port counters/quotas.
- **`-state-dir` / `-state-save` work under the shipped unit.** The systemd template now sets
  `RuntimeDirectory=wattun`, `RuntimeDirectoryMode=0700`, `RuntimeDirectoryPreserve=yes` and
  `ReadWritePaths=/etc/wattun /run/wattun`, so the documented tmpfs path `/run/wattun` is writable and the
  quota/totals counters survive a service restart. They are still lost on reboot (documented trade-off); the default
  stays next to the config.
- **Server-side client allowlist (`-allow-clients` / `-allow-clients-file`).** It restricts **holders of the PSK/token**
  to the listed IPv4/IPv6 addresses or CIDR prefixes; an unauthenticated source could never create a session anyway.
  The check is admission-only and fails closed. The list file must live under `/etc/wattun` (the unit runs with
  `ProtectHome=yes`), and `-allow-clients` together with a CDN carrier (`ws`, `wss`, `h2`, `h2c`, `grpc`) or `-sni` is
  now a startup error instead of a warning, so the operator cannot lock out every real client. The deny log is
  throttled over the whole server to 3 lines/s (burst 3) and reports the number of suppressed drops.
- **The manager cannot crash-loop an older engine.** Every 3.3.0-only setting (`state-dir`, `state-save`,
  `fec-on-loss`, `fec-off-loss`, `shape-data`, `noise*`, `allow-clients*`) is gated on the installed binary being
  3.3.0+, so a 3.2.1 engine never receives a key it would reject.
- **Deleting a tunnel really deletes its counters.** `delete` now stops the unit before removing the saved
  quota/totals files, so the engine's shutdown save cannot recreate them; a re-created tunnel starts clean.
- **Bond auto-retest (bonded Iran tunnels only, default off):** `off`/`30m`/`1h`/`6h`/`daily-offpeak` (systemd timer;
  daily at 04:15). A run re-tests the bond's legs, the carriers the auto plan left out and last run's failures with
  1 MB each way per carrier (`bondretest-budget`, `.manager.conf`, default 20 MB/run). It never removes a leg and only
  adds a carrier when no leg works at all or the candidate reaches 10 % of the best working leg's throughput.
  `wattun-manager bond-retest NAME` runs one by hand.
- **New manager commands:** `auto-prune NAME [--keep-open|--auto|--direct|--reverse-only]`, `auto-widen NAME`,
  `bond-retest NAME`; the Advanced page edits the new keys and a **Spoofing & shaping** help page explains what each
  anti-censor option hides and what none of them hide. Shaped carriers are reachable through the unattended
  `wattun kharej --carrier ...` path, a shaped token on Iran, and the interactive picker's **More transports
  (advanced)…** branch. The manager self-test now ends with 875 checks (`MGR_VERSION=2026110501`).
- **Thirteen shaped carriers (both ends 3.3.0, same carrier name).** Raw tier `sit`, `6to4` (IP protocol 41, 40-byte
  inner IPv6 header), `xfrm-ipsec` (ESP, protocol 50), `etherip` (protocol 97), `l2tpv3` (protocol 115): Linux +
  CAP_NET_RAW on both ends, bare-IP peer, one session, no reverse. UDP tier `fou-gre` 5555, `gue-ipip` 6080, `vxlan`
  4789, `geneve` 6081, `dnscrypt-udp` 443, `ntp-direct` 123, `openvpn-dco` 1194, `srtp-direct` 5004: peer/listen,
  conventional port unless the address gives one, no reverse, no multiple sessions. They are **wattun-internal wire
  shapes, not implementations of those protocols**: no inner packet is produced or parsed, a real peer of that
  protocol cannot talk to them, and they add no secrecy.
- **A shaped carrier is single-carrier only.** The engine refuses a `+` bond that contains one (exit code 2) and the
  manager refuses the same list; each shape derives its own header, and the UDP tier its own conventional port.
- **An explicit `-mtu` above a shaped carrier's ceiling is clamped with a log line** instead of silently overflowing
  the wire: raw tier `sit`/`6to4` 1360, `xfrm-ipsec` 1392, `etherip` 1384, `l2tpv3` 1396; UDP tier `dnscrypt-udp` 1326,
  `ntp-direct` 1352, `srtp-direct` 1388, `fou-gre`/`gue-ipip`/`vxlan`/`geneve` 1392, `openvpn-dco` 1396.
- **Cost of the shaped carriers:** repeated loopback runs (`go test -run xxx -bench 'ShapedUDP' -benchtime 2s ./wat/`)
  put them 0.3-4.5 % below plain `udp`; one short run scatters much more, so do not read a per-shape ranking out of a
  single run. The raw tier's end-to-end path is covered by the Linux/root CI tests; there is no live filtered-pair
  bench for either tier yet.
- **Hardening fixed before this release:** the shaped raw carriers validate direction and install a BPF filter, so a
  host that also receives its own looped protocol-41/50/97/115 packets can no longer feed a session its own frame; the
  shaped-carrier key-derivation domain strings now use the exact module path (a permanent wire constant, fixed before
  it could ship); the new float flags reject NaN/Inf; and CI gained an arm64 test job, a benchmark regression gate
  and the new shaping/noise/FEC/allowlist tests in the race subset. The release workflow now pins its third-party
  release action by full commit SHA and requires the tracked `docs/release-notes/v3.3.0.md` to exist.

## Upgrade notes

- Update **both ends** for the shaped carriers (same carrier name and key on both; the raw tier additionally needs
  Linux + CAP_NET_RAW). Everything else works in any order: no wire change to the existing carriers or frames, and
  the new `frPad2` frame is an ignorable last frame that an older peer drops without losing anything.
- No config change is required. The behavior that changes without a new key is the auto Kharej cleanup (still on by
  default, now reverse-side only; `autoprune=0` or `auto-prune NAME --keep-open` disables it) and the wider
  `autowiden` default of 10 minutes.
- If you already use `-allow-clients` on a CDN carrier or with `-sni`, the server now refuses to start instead of
  silently rejecting every client: remove the list or move to a direct carrier. `-allow-clients-file` outside
  `/etc/wattun` is a startup error too.
- `shape-data` and `noise` spend real bandwidth and stay off by default; set them only when a size or idle classifier
  is the problem.
