**Tunnel status now tells the truth, and an auto Kharej cleans up after itself.**

Tunnels that were connected no longer show `waiting` or `degraded`, and the auto test no longer reports a false failure when tuning a reverse type. The carriers Iran doesn't use now close on both sides about 5 minutes after it picks one. Only the manager changed, so the engine does the same work as 3.3.0 and old and new peers work together. Update both servers: run `wattun update` on each.

## Changes in detail

- **Real status on an auto Kharej.** An auto tunnel runs as two units, `NAME` and `NAME-r`, and each one reported only itself. `NAME` said `waiting` while Iran was connected through `NAME-r`. Both now read the pair:
  - `up` when the link is on either side, and the page names the side.
  - `standby` for the side Iran isn't using.
  - `waiting` only when neither side has a link.
- **No answer is not "no link".** A busy server can miss the 2 s limit on `/stats`, which used to show as `down`. The manager now tries twice, then shows `unknown`.
- **`degraded` is now `partial`, with the reason.** It appears only when a bond leg is down, for example `1 of 3 carriers down`. Packet loss no longer changes the status; it stays a row on the page.
- **The reverse side shows its real carrier.** The `NAME-r` page shows `tcp (picked by Iran)` instead of every open type.
- **Test tunnels no longer stay open on Kharej.** The automatic cleanup used to close only the unused reverse side, 12 minutes after Iran's pick, so the direct unit kept every carrier open. It now closes everything unused on both sides after 5 minutes:
  - Each close restarts the side that stays open, so its connections drop once.
  - Configs and tokens stay.
  - `autoprune-direct=0` in `.manager.conf` limits the cleanup to the reverse side, and `auto-prune NAME --keep-open` turns it off for one tunnel.
- **Bonds keep every leg.** The cleanup now reads each live leg from `carriers[]` in `/stats`, so a bonded Iran client keeps them all.
- **Changing type after a cleanup.** Run `wattun-manager auto-widen NAME` on Kharej first, because a re-test on Iran only sees what is still open. If you skip it, the manager reopens everything after 3 failed checks.
- **A narrowed reverse tunnel stays narrowed.** With one carrier left, `/stats` lists no `carriers[]`, so the manager saw nothing in use and reopened everything about 2 minutes after each cleanup, restarting the link. Measured on a live pair after the fix: closed and connected for 8 minutes, with no reopen.
- **Auto test tuning on reverse types.** It printed `no link in 8 s` for a tunnel that connected moments later, because the Kharej dialer backs off for up to 30 s. Reverse tuning and link waits now allow 45 s.
- **A stopped reverse side leaves the status lists.** The parent tunnel stays listed and shows the merged status.
- **Docs.** Both READMEs now start with the install steps, and the old "what changed since" sections are gone. The release history stays in `docs/TECHNICAL.md`.
