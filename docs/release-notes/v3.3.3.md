**After Iran picks, the type it uses becomes the tunnel and the test listeners are deleted.**

An auto Kharej tunnel no longer leaves test listeners behind, and deleting it never takes down the side Iran is connected through. Only the manager changed, so old and new peers work together. Run `wattun update` on each Kharej server; Iran servers see no change.

## Changes in detail

- **The pick becomes the tunnel.** Once Iran's pick has held for 5 minutes and the unused carriers are closed, the next heal pass (about a minute later) keeps the one type Iran uses as the tunnel, under the same name.
  - A reverse pick moves `NAME-r` into `NAME`, with the same key and traffic counters. A shaped pick moves its hidden listener the same way. A direct pick keeps `NAME`.
  - Everything else is deleted: the reverse side, the hidden test listeners, their firewall rules and the auto token. The dashboard then shows one ordinary tunnel.
  - The tunnel restarts once, so its connections drop once.
  - The kept tunnel has no `c` switch, no `auto-widen` and no automatic reopen, and no token to show. To test other types again, make a new auto tunnel.
  - Nothing is deleted while Iran is not connected, while its pick cannot be read, or when Iran bonds across both sides. `autoprune-direct=0`, `autoprune=0` and a tunnel held open from the menu also keep it as it is.
- **Auto tunnels that are already closed get converted.** After the update, an auto tunnel whose carriers were already closed is converted on its first heal pass.
- **Deleting the test tunnel keeps Iran's link.** Deleting an auto tunnel while Iran runs on its reverse side or a hidden listener keeps that link as the tunnel and deletes only the test parts. Delete it again to remove it completely. Before, it also deleted the reverse side Iran was using.
  - When the manager cannot read which side Iran uses, it names the side that is still running before deleting.
  - The delete warning now lists everything that goes with the tunnel.
- **New tunnels no longer take a port an auto tunnel owns.** The port check now reads the `listen-ws:`, `listen-wss:` and other per-carrier lines of every config, stopped ones too. Before, a second auto tunnel could pick port 2052 that the first one owned and then fail with `bind: address already in use`.
