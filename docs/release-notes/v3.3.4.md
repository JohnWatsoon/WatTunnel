**Faster uploads on untuned servers: the kernel speed boost is now on by default.**

On a production Iran server with the kernel's default settings, the tunnel's upload went from 49 to 66-72 MB/s once the boost was applied. Run `wattun update` on both servers. Old and new peers work together, but the boost and the higher connection cap only take effect on a server that runs 3.3.4.

## Changes in detail

- **Boost on by default.** The installer and `wattun update` now apply the kernel boost on every server: BBR, the `fq` qdisc and 64 MB socket buffers.
  - Measured on a production pair (Iran 2 vCPU, 88 ms to Kharej, reverse `ws`). The untuned Iran kernel (cubic, `pfifo_fast`, 212 KB buffers) moved 7 MB/s up over 16 raw TCP connections, and 68 MB/s after the boost. The tunnel's upload went from 49 to 66-72 MB/s.
  - Containers are skipped, and so is a server where `wattun-manager boost --undo` was run. `boost --yes` turns it back on.
- **Boost takes effect at once.** It used to set `fq` only as the default for interfaces created later, so the network card kept `pfifo_fast` until a reboot. Now it switches the card to `fq` right away. A custom qdisc (`htb`, `cake`, `tbf` ...) is left alone.
- **Emulated network card warning.** `wattun-manager boost status` now names an emulated card such as `e1000`, and says to ask the provider for a `virtio` one. On the same Iran server the `e1000` card kept one CPU core at 95 % softirq and held the download near 85 MB/s. No setting fixes that, only a different card.
- **More connections per user address.** The Iran listeners now allow 1024 connections per source IP instead of 256, because mobile carriers put many users behind one address. That production server had refused 242 user connections at the old cap.
