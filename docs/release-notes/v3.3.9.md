**Security seals, the emergency-token round trip fixed, directional bond legs, `-mtu-adapt`, and `wattun mute`/`unmute`.**

Run `wattun update` on both servers (or on Kharej run `wattun bundle`, copy `wattun-offline-amd64.tar.gz` to Iran, and run `wattun update --from wattun-offline-amd64.tar.gz`). Old and new peers interoperate: the only new frame (`frEndpoint`, type 0x0e) rides at the end of an ordinary packet and is ignored by older peers, and every new feature is off unless you turn it on.

## Summary

- **Security seals.** Four audited holes closed: the tunnel no longer downgrades its own header encryption under packet loss; HTTP-family tunnels no longer answer active probers with a real `101`/`200`; `udp-dns`, `ntp-direct` and `srtp-direct` frames are now protocol-valid instead of protocol-shaped; `-no-pq` can no longer be defeated by newly standardized post-quantum curves.
- **The emergency token now describes the tunnel it arms.** `arm-blackout` finalizes a multi-carrier bond, but the printed token used to describe the pre-arming single carrier — during a blackout you would copy a token that could not reconnect. Fixed and proven by an export → import test.
- **Directional bond legs.** Give one leg of a bond a single direction (`carrier: tcp:up+udp:down`) — e.g. keep a proven uplink free of downlink traffic, or steer the downlink onto a receive-only udp leg. Both ends need 3.3.9.
- **`-mtu-adapt` (off by default, per end).** When an ISP drops large packets while small ones pass, the payload on that path shrinks to 640 B for 30 s at a time — no restart, no wire signal, invisible to the peer.
- **`udp-hop` (Wraith), Iran side only.** For routes that cut each UDP flow after ~30 packets: the udp carrier sends from a new source port every 12-18 packets. Kharej needs no update. The Iran auto test tries it as a `udp hop` row.
- **`wattun mute NAME PATH` / `wattun unmute NAME PATH`.** Take one bonded leg out of service by hand and put it back, without restarting anything.

## Changes in detail

- **`udp-hop N` (client, udp carrier).** A fresh UDP socket every N to 1.5N packets (jittered), destination port unchanged; an old socket keeps receiving for 0.5 s. The server already replies to the newest authenticated source, so no wire or server change. Field basis (iran2 to kharej): a fixed flow is cut after ~29-34 packets at any size and port; rotating only the source port delivered 99.7 % (2026-11-14), and a 12-20-packet raw-socket rotation 98.7 % (2026-11-20). That raw sender topped out near 27 MB/s on the 2-core iran2. Batching (sendmmsg) is off on a hopping socket. Manager: Advanced `h` on Iran udp tunnels, and a `udp hop` auto-test row (engine 3.3.9+).
- **Repaste notice after token recovery.** When the manager rebuilds a lost auto token on Kharej (3.3.3-3.3.7 finalize removed it), the carriers move to new ports. Until that token is shown (`t`), Kharej's dashboard and tunnel page now say to paste it on Iran. Iran's "no carrier reached" screen names this as a cause.

Security (`wat/`)
- **No more automatic header downgrade.** A client flipped its header form to plaintext after 3 s of silence before the first authenticated packet (and again after a 30 s reset), so a filter only had to drop packets at flow start to read the session id and packet number in clear; the server then latched to the peer's form per authenticated packet. The guessing is gone; `-legacy-mask-flip` restores it explicitly for joining a pre-3.0 peer.
- **`-probe-guard` (both ends, off by default).** Before it, a scanner that sent a websocket upgrade (or an h2/grpc POST) to the tunnel path received a real `101 Switching Protocols` / `200 OK` before any key check. With the flag, the server demands a key-derived `X-Request-Id` token (10-byte HMAC over a 5-minute bucket + method + path, ±5 min clock skew) before answering, and hands everything else to the decoy or the nginx pages. A prober learns nothing.
- **`-no-pq` is an allowlist.** The old three-curve denylist could not know about newly standardized post-quantum groups (Go 1.26 ships `SecP256r1MLKEM768`/`SecP384r1MLKEM1024`; utls has `P256Kyber768Draft00`); any of them leaking into a `-no-pq` ClientHello would bloat it past the size window that survives Iranian DPI (measured 2026-10-22: 1474 B hellos vanish, 250–512 B pass). Now only `X25519`, `P-256`, `P-384`, `P-521` survive the filter.
- **Shaped carriers are protocol-valid.** `udp-dns-edns` (opt-in, both ends): queries carry an EDNS0 OPT record and the server replies as a real answer that echoes the query's id and question with the tunnel packet as TXT RDATA (a legacy query still gets the legacy reply, so the server can upgrade first). `ntp-direct`: server replies carry stratum 2 (stratum 0 is a Kiss-o'-Death packet), real NTP-epoch timestamps, the originate timestamp echoes the client's, and the payload rides an NTS-cookie extension field instead of bare ciphertext. `srtp-direct`: directional SSRCs (a real RTP session never uses one SSRC both ways) and a timestamp that wraps like a real 8 kHz RTP clock instead of every 65536 packets.
- **TLS session resumption.** The `tls` carrier's reconnects resume the TLS 1.3 session instead of paying a full ECDHE handshake per dial (the uTLS fingerprint path is untouched).

Emergency token (M1) (`wattun-manager`)
- `refresh_token` regenerates a bonded Kharej tunnel's token from the finalized config: the carrier list, one endpoint per leg (`listen-<carrier>:` ports in carrier order), the finalized path/sni/icmp-type, and no stale auto plan. Bond tokens carry one endpoint per leg (comma form in the peer field; single-carrier tokens are byte-identical to before, so older managers and tokens still parse). The Iran import writes `peer-<carrier>:` per leg, so every pool leg dials its own armed listener. Token writes are atomic (tmp + rename, umask 077). Proven by a `test-manager.sh` sandbox case: arm a bond → export the token → import into an empty config → the imported carrier list, per-leg endpoints, allowed ports and path equal the finalized server settings.

Directional bond legs (`:up`/`:down`) (`wat/`, both ends 3.3.9)
- A bond leg may carry one direction only: `carrier: tcp:up+udp:down` keeps a proven uplink leg free of downlink and gives the downlink its own receive-only udp leg. `:down` is udp-only in this version; each carrier appears at most once per bond; every bond must keep at least one leg per direction; a suffix outside a `+` bond is refused.
- The server learns a client's receive-only leg from the new `frEndpoint` frame (type 0x0e, last frame in an authenticated uplink packet, ignored by older peers): it carries only the leg index and the client's bound port — the IP always comes from the packet's authenticated source address, so nothing is on the wire to reflect.
- Mixed versions degrade safely: an older server ignores the frame and never sends down the down leg; the uplink (and any bidirectional legs) keep working.

Adaptive payload clamp (`-mtu-adapt`, per end, off by default)
- 8 consecutive lost packets beyond 512 B clamp that path's payload to 640 B for 30 s; the hold expires by itself and the detector re-fires while the losses persist; any ack resets the loss run. The clamp is per path inside a bond and never exceeds the configured `mtu`. There is no wire signal: each end watches its own send paths, so it is invisible to the peer and safe with mixed versions.

Manual path mute (`wattun-manager`)
- `mute NAME PATH` / `unmute NAME PATH` talk to the running tunnel's metrics endpoint (`POST /carrier/toggle`); PATH is the leg's carrier name from `/stats` (`udp`, or the suffixed leg `udp:up`) or its bond-page index. No restart, no root needed for these two commands. `/stats` keeps `muted: true` next to the leg's real `alive` state, so an operator override is distinguishable from a dead leg.

Manager
- Suffixed legs validate (`carrier_ok` strips the suffix; the bond rules — udp-only `:down`, one leg per direction, bond-only suffixes, no shaped legs — are enforced with exact error texts), round-trip through tokens and configs, and are gated to 3.3.9 by `carrier_min_ver`. `MGR_VERSION` is 2026111901.

Known limitations
- `:down` legs are udp-only in this version; pool-carrier down legs need endpoint signaling design work.
- The adaptive clamp's detector is deliberately conservative (8 losses in a row); a path that loses exactly 7 large packets per burst never clamps — raise `-mtu` down manually in that case.
- Live Iran↔Kharej verification of the new features is operator-run (`deploy.sh`); the simulator evidence is in `wat/bifrost_test.go`, `wat/hornet_test.go`, `wat/phoenix_test.go`.
