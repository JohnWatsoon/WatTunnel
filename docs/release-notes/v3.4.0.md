**Faster bonding, Kharej Auto tunnels that keep every carrier open, offline updates for Iran, security fixes, and `udp-hop` for routes that cut each UDP flow after ~30 packets.**

Update both servers: run `wattun update` on each, or on Kharej run `wattun bundle`, copy `wattun-offline-amd64.tar.gz` to Iran and run `wattun update --from wattun-offline-amd64.tar.gz` there. Old and new peers keep working together during the upgrade. Every new engine feature is off until you turn it on. 3.3.8 and 3.3.9 were never published; this release contains both.

If an Iran auto test shows every carrier failing after Kharej updated: Kharej recovered its lost auto token on new ports. Open the tunnel on Kharej, press `t`, and paste that token on Iran. The Kharej dashboard now says so.

## Changes in detail

Source-port hopping (`udp-hop`, Wraith)
- **What it does.** `udp-hop: N` on the Iran (client) side makes the udp carrier send from a new UDP source port every N to 1.5N packets (jittered). The destination port stays fixed. An old socket keeps receiving for 0.5 s. The manager offers it under Advanced (`h`, Iran udp tunnels), and the Iran auto test adds a `udp hop` row after `udp`.
- **Why.** On the iran2 to kharej test pair, the Iran to Kharej direction cuts each UDP flow after ~29-34 packets, at any size and port. Plain udp dies there. Rotating only the source port delivered 99.7 % of packets (2026-11-14).
- **Measured (2026-11-20, same pair).** Plain udp: cut, link dead within seconds. udp-hop 12: link stays up; upload 8.9-10.4 MB/s with ~3 % retransmits.
- **Pacing for hopping.** Each source port can take its own path, so RTT spreads (77-110 ms on that pair) and packets arrive out of order with no real queue. The first build read that as congestion: 98.8 % of uplink packets arrived, yet 35 % were declared lost and upload sat at 1-4 MB/s. The hopping client now judges delay by the fastest sample of each tick and loss by age.
- **Kharej version.** Any Kharej connects; the server follows the newest source port. A 3.4.0 Kharej also notices a hopping client (8 source-port changes) and paces its downlink the same way. An older Kharej keeps cutting its downlink on the RTT spread, so update Kharej too. This server-side step is covered by tests but not yet measured on the field pair.

Kharej Auto tunnels
- **One tunnel, all carriers open.** An Auto tunnel on Kharej is one entry (`NAME`), with its hidden `NAME-r` and `NAME-e-*` helpers aggregated into it. Every planned carrier stays open; auto-narrow, auto-prune, auto-finalize and the manual open/close/undo keys are gone. Tunnels that 3.3.3-3.3.7 narrowed or finalized reopen automatically, keeping their `ports:` allowlist.
- **Lost token recovered.** A 3.3.3-3.3.7 finalize deleted `NAME.token` ("No token stored"). The manager rebuilds it. The recovered plan uses new ports, so Kharej's dashboard, tunnel page and token screen say to paste it on Iran until you show it (`t`).
- **Random free ports.** New tunnels pick verified-free random ports in 10000-32767 instead of 80/443/8443/4443 and friends. With a CDN domain they pick Cloudflare's non-443/80 proxy ports. Each Kharej Auto tunnel gets its own reverse port block, so a second reverse tunnel no longer collides with the first.
- **Reverse bonds.** In the Iran auto test, `c`/`b` now join two or more reverse rows into one reverse bond (it failed with "ws reverse is a reverse connection; it cannot be joined with others").

Updates and install in Iran
- **Offline bundles.** `wattun bundle [amd64|arm64]` on Kharej builds a signed bundle; `wattun update --from FILE` installs it on Iran. Settings `p` sets an update proxy. `install.sh` offers proxy or bundle recovery when GitHub is blocked.
- **IPv6.** Wizards, tokens, companions and validators accept `[v6]:port`, bare v6 and `::`.

Bonding and engine
- **Bonded throughput.** Bonds keep late-ACK immunity and full window headroom, forward pool backpressure and connection deaths, clamp frames to each path's MTU, keep HTTP carriers at 4 KB behind CDNs while tcp/tls/reverse pools use 16 KB, track each path's minimum RTT apart from srtt, and pace mixed icmp+pool bonds at pool speed while a pool leg is healthy.
- **Directional legs.** A bond leg may carry one direction only (`carrier: tcp:up+udp:down`; `:down` is udp-only). The server learns the client's receive-only leg from a new frame (`frEndpoint`, 0x0e) that older peers ignore. Both ends need 3.4.0 for it; a mixed pair keeps working on bidirectional legs.
- **`-mtu-adapt` (off by default, per end).** 8 lost packets in a row larger than 512 B clamp that path to 640 B for 30 s. No wire signal.
- **`wattun mute NAME PATH` / `unmute`.** Take one bonded leg out of service and put it back without a restart; `/stats` shows `muted`.

Security
- **No automatic header downgrade.** A client used to switch to the plain header after 3 s of silence at flow start, so a filter could read the session id by dropping early packets. `-legacy-mask-flip` restores it only for pre-3.0 peers.
- **`-probe-guard` (both ends, off by default).** ws/wss/h2/h2c/grpc tunnels answer only requests carrying a key-derived token; a scanner gets the decoy or nginx pages, never a real `101`/`200`.
- **`-no-pq` is an allowlist.** Only X25519, P-256, P-384 and P-521 pass, so new post-quantum groups cannot push the ClientHello past the size Iranian DPI drops (1474 B vanish, 250-512 B pass, 2026-10-22).
- **Shaped carriers are protocol-valid.** `udp-dns-edns` (opt-in, both ends) sends real EDNS0 queries and TXT answers; `ntp-direct` replies carry stratum 2 and real timestamps; `srtp-direct` uses per-direction SSRCs and a wrapping 8 kHz clock.
- **Hardening.** `wprobe` caps replies (no ICMP amplification); malformed `-allow-ports` stop startup; reverse-pool connections are isolated until authenticated; quota periods and size values are validated.
- **Emergency token.** `arm-blackout` now prints a token that describes the armed bond (one endpoint per leg), not the pre-arming carrier. Proven by an export and import round trip.
- **TLS resumption.** The `tls` carrier resumes TLS 1.3 sessions on reconnect instead of a full handshake.

Manager
- **New look.** `install.sh` and `wattun-manager` screens were cleaned up: one accent colour, quiet borders, live download and probe gauges.
- **Go manager preview.** `WAT_GO_MGR=1 wattun` opens the manager rewritten in Go (wizards with a step bar, a live tunnel page). The bash manager stays the default.
- **Panel warning.** The Iran port editor warns when a panel inbound is unencrypted.
