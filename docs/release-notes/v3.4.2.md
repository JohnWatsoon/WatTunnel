**Fix: New tunnel → auto works again. `wattun` opens the bash manager again.**

In 3.4.1, `wattun` opened the new Go manager, and its auto wizard was broken: on Kharej the process ran out of memory and was killed before it wrote anything or showed a token, and on Iran it refused auto tokens. Run `wattun update` on any server that has 3.4.1. Tunnels that are already running were never affected, and the wire format is unchanged, so one end can update before the other.

## Changes in detail

- **Bash manager is the default again.** `wattun` with no flags hands over to `wattun-manager`, as in 3.4.0 and before. The Go manager stays an opt-in preview (`WAT_GO_MGR=1 wattun`) until it can create auto tunnels on both ends.
- **Go manager: auto key fix.** New tunnel → auto on Kharej read `/dev/urandom` as a whole file, which never ends, so memory grew to about 1.5 GB until the kernel killed the process. It now makes a random 40-character key the same way the fixed-type wizard does, and ends on the token screen.
- **Go manager: menu numbers.** Every menu row shows the number (or letter) that opens it, and the home screen's key line says `1-6 jump`.
- **Go manager: colours over SSH.** SSH does not pass `COLORTERM`, and PuTTY and Termius send plain `TERM=xterm`, so the menu fell back to 8 colours (no gradient, no highlight bar). Any `xterm*`, `screen*`, `tmux*` or `rxvt*` terminal now gets 256 colours; `WAT_COLORS=24` forces truecolor, `WAT_COLORS=8` the plain set.
