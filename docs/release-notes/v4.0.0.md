**4.0.0: a web panel on the Iran server, Kharej managed from Iran, and old tunnels link Kharej by themselves.**

Iran now has a web panel (`wattun panel on`) and manages its Kharej servers over the tunnel itself: status, tests, carrier changes, new tunnels and updates, with no SSH to Kharej. Update **both** servers: tunnels made before 3.5 then link their Kharej on their own, with no token to paste. Running tunnels keep working during the update, and old and new peers still talk to each other. 3.5.x and 3.6.x were never released, so everything they added ships here.

## Changes in detail

- **Web panel (Iran).** `wattun panel on` starts an HTTPS panel on a random port with a random path, a self-signed certificate for this server's IP, a password and optional 2FA (TOTP). It shows the tunnels, live throughput, traffic per day and per tunnel, speed tests, alerts, the Kharej servers and this server's health. It can create, edit, restart, test and delete tunnels, change carriers, set quotas and port limits, back up and restore, and update every server at once. Dangerous actions need a slide to confirm, and full-access actions ask for the password when 2FA is off. Phones get a bottom bar and a quick action button.
- **Kharej managed from Iran (Scepter).** The tunnel carries a hidden, encrypted management channel. From Iran you can read Kharej's state, stats, logs and events, create tunnels on Kharej and here in one go ("On Kharej and here"), change a carrier with automatic rollback, run carrier tests, update Kharej, run doctor, back up, and read the audit log. Kharej checks, rate-limits and logs every command, never forwards to its own SSH, metrics or latch port, and only its own console can revoke the pairing.
- **Pairing in one step.** On Kharej, `wattun pair-token` (or `t` on the dashboard) prints a pairing token; on Iran, `wattun add-kharej --token wat1:...` (or Add Kharej in the panel) tests which carriers reach Kharej and pairs. One Iran can add several Kharej servers. The link it uses is hidden from tunnel lists and kept alive by heal.
- **Auto-link for old tunnels.** A tunnel made before 3.5 has no pairing in its token. Once both ends run 4.0.0 it pairs at full rights from the key both ends share; the first Iran that connects claims that Kharej. Updating Iran first is fine: it links within 30 seconds of Kharej's update, without a restart (checked against a 3.4.2 Kharej: forwarding untouched, no log noise). `pairing: false` in a tunnel's config opts it out. Anyone holding an old tunnel token could claim that Kharej first, so update Iran before or together with Kharej. To move a Kharej to another Iran: `wattun pair-token` on Kharej, then `wattun add-kharej` on the new Iran.
- **Carrier test.** The test card shows the preset you chose and the carrier being tested, and has Skip (this carrier) and End test (keep the current carrier and choose one yourself). The reverse-only preset now tests only reverse carriers; before, a re-test ran the normal set.
- **New carriers.** `ptcp` (fake TCP on a raw socket with port hopping) and `spray` (raw UDP with a new 5-tuple every few packets), both Linux and root only. Auto's extended preset also tests the shaped carriers, and Kharej keeps every test carrier open.
- **Go manager is the default.** `wattun` opens the Go manager with role-aware dashboards, a live monitor chart, the Kharej servers screens and the operations console. `WAT_BASH_MGR=1 wattun` still opens the bash manager.
- **Fixes.** The Kharej connection cap counts tunnels; the speed test reports live and fails fast; heal uses less CPU; an auto create no longer resets its stream; ptcp and spray tunnels can be created from Iran again; Iran's claim store no longer loses a line when several tunnels pair at the same moment; a refused pairing says which Iran manages that Kharej instead of asking for a newer version.
- **Opt-in tuning (off by default).** `-fast-rtx`, `-repair`, `-burst-cap` and `-rate-tune` are measurement knobs. None of them made the target path faster in testing, so none is on by default.
- **Upgrading.** Run `wattun-manager update` (or the installer) on both servers. An update from before 3.6.0 prints what is new and the one step left; the panel stays off until you run `wattun panel on`.
