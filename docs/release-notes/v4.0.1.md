**The panel now does what the manager does: every advanced setting as one-tap presets, anti-censorship per tunnel, start at boot, and a real traffic graph.**

Open a tunnel in the panel and its new Settings section has every option from the manager's Advanced page, each with ready presets and a custom value. Pick what you want and apply it all with one restart. Update the Iran server for the panel features; update Kharej too for the lower memory use and so settings that must match on both ends can be changed from Iran.

## Changes in detail

- **Tunnel settings in the panel.** Speed limit, sessions, connections, packet size, window, batching, UDP hop, slow down on loss, error correction, padding, idle traffic, probe guard, ICMP type, listen address and counter saving. Each one is a row of preset chips plus Custom, which accepts the same ranges as the manager. Changes collect in a bar at the bottom and apply together with a single restart.
- **Settings that must match on both ends** (probe guard, ICMP type) change on Kharej first through the pairing. If Kharej refuses, nothing changes on Iran, so the link cannot end up half-changed. Kharej refuses edits to the tunnel that carries the panel's own connection to it; change that one on Kharej's console.
- **Anti-censorship per tunnel.** Off, Cloudflare, Fast, MCI whitelist, Irancell whitelist, Low churn and Blackout, applied on the end that dials. For a reverse tunnel that is Kharej, so the panel sends it there. "Test what passes the filter" runs the manager's anti-censorship test.
- **Start at boot** is a switch, with no restart. **Diagnose** runs the manager's full tunnel check, including a 10 MB speed test.
- **Real traffic graph.** The tunnel graph used to show the pacing rate, not traffic. It now draws real download and upload from the engine's byte counters, with latency dashed. Loss is now packets resent over the last 30 seconds instead of a single 50 ms window, so it no longer jumps between 0 and high values.
- **Crash-loop alert.** A tunnel that systemd restarts 3 or more times in 5 minutes now raises an alert. The "down" alert missed this, because such a tunnel is up for a moment between crashes.
- **Certificate when port 80 is taken.** Iran servers often forward port 80 through a tunnel, so Let's Encrypt's port 80 check failed. The panel now uses the TLS check on port 443 instead, and only refuses when both ports are busy. The wrong Skip button on the certificate card is gone.
- **System page:** CPU use, split into what the tunnels use and what everything else on the server uses. Versions lists Kharej servers by their address.
- **Smaller fixes:** port cards show the 4 busiest first, with a "Show all" button. The map's packet animation no longer stutters or restarts. Run a test is a normal button. The browser tab is named WatTunnel after sign-in.
- **Less CPU and memory.** Each forwarded connection now reuses its copy buffers instead of allocating new ones. Measured on a live pair at about 2 MB/s with roughly 300 connections: Iran went from 207 to 181 CPU-seconds per GB (−13%) and its wattun memory from 141 to 115 MB. Kharej went from 110 to 105 CPU-seconds per GB and from 128 to 83 MB (part of that drop is the fresh restart).
