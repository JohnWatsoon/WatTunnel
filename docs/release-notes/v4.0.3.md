**Cloudflare (CDN) rows are back in the auto test, ports move between tunnels, and the panel has the manager's tuning tools.**

Update both ends. On Kharej, create an auto tunnel that should go through Cloudflare again, with the domain, to get CDN rows in the test.

## Changes in detail

- **CDN rows in the auto test again.** Since 3.3.9 a new auto tunnel on Kharej did not listen on wss, h2 or grpc, and it ignored `--cdn-domain` when it picked ports. So the test never had a Cloudflare row, even with a domain. Both are fixed: with a domain, wss and grpc sit on ports Cloudflare proxies. Tunnels made with 3.3.9-4.0.2 must be created again on Kharej with the domain. A domain given only on Iran cannot help.
- **Domain in the panel.** The panel's *On Kharej and here* form has a *Cloudflare domain* field for auto tunnels. An older Kharej ignores it.
- **Move ports.** An Iran tunnel's drawer has *Move ports*: tick ports and pick another Iran tunnel. If the target is paired, the missing ports are added to its Kharej allowlist first. If that fails, the source keeps its ports. CLI: `wattun move-ports FROM TO "8443:443"`.
- **Tune tools in the panel.** The tunnel drawer runs *Find best anti-censorship* (`matrix`), *Tune Cloudflare path* (`cdn-tune`), *Re-test bond legs* and *Reset traffic* as jobs. Each applies its best result.
- **System: Speed and access.** The kernel speed boost and its undo, *Re-test auto tunnels* now, and the Iran-only client firewall on or off.
- **Panel password shown at install.** A leftover Enter could skip the "Save the login" pause, so the password scrolled away unseen. The installer now drops type-ahead first. `wattun panel` also says how to reset a lost password (`wattun panel reset`).
- **Settings look.** Start at boot and Anti-censorship are rows in one list, with the same track as the other settings.
