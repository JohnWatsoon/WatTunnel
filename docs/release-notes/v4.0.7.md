**ptcp and spray work on Iran servers with 2 or more CPUs.**

Update the Iran side. Kharej needs nothing new.

## Changes in detail

- **ptcp and spray no longer exit at start.** On a client host with 2 or more CPUs the engine picks more than one session by itself. It already skipped the raw-IP and shaped carriers, but not ptcp and spray, so they asked for a second session, logged `-sessions > 1 is not supported on this carrier` and exited. A carrier test then showed "no link in 8 s" for both. Now only the carriers that can run several sessions (tcp, tls, ws, wss, h2, h2c, grpc, udp) get more than one. On our test pair ptcp now measures 6.7 MB/s and spray 7.8 MB/s down (5 MB probe), where both had no link before.
