**One card per Kharej server, new tunnels through a reverse tunnel work, and only deleting asks for the password.**

Update both ends. Iran gets the panel fixes; Kharej starts telling Iran its address, which a reverse-only Iran needs to name the server.

## Changes in detail

- **One Kharej, one card.** The panel told Kharej servers apart by each tunnel's peer address. A reverse tunnel's peer is often this Iran server itself, or missing, so one Kharej showed up once per tunnel: named after the tunnel (`rws1`) or after Iran's own city (TEHRAN). A reverse tunnel now finds its Kharej from the connections Kharej makes to it, and every tunnel to the same server shares one card, named by where that server is.
- **New tunnel on Kharej and here, through a reverse tunnel.** When the panel reached Kharej through a reverse tunnel, it could not build the new tunnel's token ("Kharej made the tunnel but its token could not be built here"). Picking a carrier by hand (icmp, gre and the rest) failed this way, and each try left the name taken on Kharej. It now uses the same Kharej address as above.
- **Kharej sends its address.** Kharej's answer to the panel was meant to carry its public IP since 4.0.1, but the tunnel process never looked it up and always sent an empty one.
- **Only deleting asks for the password.** Deleting a tunnel (here or on Kharej), removing a Kharej, restoring a backup and changing the panel's own access still ask for it. Moving ports, showing a token, updating, rolling back, rotating keys and pairings, downloading backups and certificates no longer do.
- **Re-measure stage in the carrier test.** After the first pass the test re-measures the fastest few with a longer run. The card now says so (*Re-measuring 2 of 3*): the other squares fade, the one being measured pulses a ring and the finished ones get a tick. Before, the card looked finished while it was still measuring.
